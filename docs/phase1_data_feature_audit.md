# Phase 1 Data + Feature Audit

## Scope

This audit covers current backend data providers, ML data ingestion/feature generation, inference feature dependencies, tests, and docs.

## Real Data Sources (Current)

- Cricket historical data path is real and reproducible:
  - `ml.data_ingest` parses Cricsheet IPL JSON into:
    - `data/processed/matches.csv`
    - `data/processed/player_match_stats.csv`
- Cricket live/upcoming provider path is real-capable:
  - `CricAPIRealtimeProvider` with timeout/retry/cache/stale-cache behavior.
  - Uses env-configured API key and degrades to cache/historical modes.
- Football data currently present in processed files is generated by bootstrap script, not a true external ingestion pipeline.

## Fallback Paths (Current)

- Catalog provider defaults to `local-demo`, backed by local processed CSVs.
- Realtime provider supports:
  - `cricapi` (real when key/network available)
  - `mock-realtime` deterministic synthetic feed.
- ML feature generation has deterministic bootstrap mode in `ml.features` and `ml.football_features`.
- Prediction service has heuristic fallback for model/runtime failure.

## Strong Features / Behaviors (Current)

- Time-ordered training split and artifact persistence exist.
- Provider cache handling is robust:
  - stale cache support
  - corrupted cache safety
  - partial live payload handling tests
- Current feature set includes useful recent-form and venue/head-to-head signals.
- Residual and anomaly hooks are present in prediction metadata.

## Weak / Noisy / Risky Areas (Current)

- Primary runtime defaults still favor demo/mock behavior:
  - `data_provider=local-demo`
  - unknown realtime provider falls back to mock.
- `mock_realtime_provider` exposes synthetic live/upcoming matches that can appear in catalog merge path.
- `local_demo_provider` contains synthetic fallback football players in primary provider path.
- Live provider emits legacy feature keys, while ML now uses upgraded schema; mapping exists but is loose and not centrally validated.
- Feature pipeline can still auto-bootstrap synthetic cricket dataset if processed files are missing, which is risky for production truthfulness.
- Football path is acceptable as secondary but still bootstrap-heavy and should not appear as “live-real” behavior.

## Planned Changes in This Phase

1. Harden provider truthfulness:
   - Keep mock/demo paths only as explicit fallback, not implicit primary behavior.
   - Prevent synthetic live matches from leaking into primary catalog flow.
2. Tighten tournament/coverage surfacing:
   - Only return tournaments with real usable match rows.
   - Ensure state/tournament filters fail cleanly on unsupported combinations.
3. Strengthen feature pipeline robustness:
   - deterministic output shape for required feature columns
   - stronger guards for missing team/venue/head-to-head/live payload gaps
   - prune weak duplicate or stale compatibility logic in feature-building path
4. Align live feature normalization to upgraded feature schema cleanly.
5. Keep fallback internal and silent where possible, while preserving no-crash behavior.
