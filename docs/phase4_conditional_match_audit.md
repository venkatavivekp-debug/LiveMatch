# Phase 4 Conditional Match Audit

## Current Batting-Order / Chase-Defend Logic

- `ml/features.py` has one-row-per-match training data with `batting_first` and venue chase signal.
- `ml/model.py` predicts full score pair (`team_a_score`, `team_b_score`) plus winner probability per head.
- `ml/inference.py` currently predicts one scenario score pair and then builds `team_a_first` / `team_b_first` branches using mirrored mapping (`_cricket_match_branches`) plus a small venue shift.
- `backend/app/services/prediction_service.py` already evaluates historical matches against the correct branch when batting order is available.

## What Is Real vs Weak

Real / strong:
- Ensemble-based score-pair forecasting and winner head.
- Branch-aware evaluation selection for completed matches.
- Robust fallback behavior, provider guards, and API contract coverage.

Weak / underused:
- Branch outputs are not generated by two conditional model passes.
- Chase/defend strength is not explicit in feature columns.
- Existing branch winners can stay effectively fixed because both branches come from one base prediction pair.

## Misleading Outputs Today

- `team_a_first` and `team_b_first` can look like formatting variants rather than true conditional forecasts.
- Winner differences across batting order are possible but not strongly data-driven.

## Data Fields Missing or Weak

Missing in core feature set:
- `team_a_bats_first`, `team_b_bats_first`
- `team_a_chase_success_rate`, `team_b_chase_success_rate`
- `team_a_defend_success_rate`, `team_b_defend_success_rate`
- differential chase/defend edge features tied to batting order
- stronger relative form features (`recent_form_diff`, `recent_run_rate_diff`, `head_to_head_win_diff`)

## Code/Data Paths To Remove Or Tighten

- Remove branch mirroring dependency in cricket inference (`_cricket_match_branches`) for primary prediction path.
- Remove stale fallback score branch shortcuts where one branch is derived from static transformation.
- Tighten feature defaults for new conditional columns to avoid zero-biased branch behavior.

## Required Robustness Checks

- Conditional inference with full ensemble, partial ensemble, and single-model fallback.
- Graceful behavior when batting-order fields are missing in historical lookup.
- Consistent output shape when live context is absent.
- Evaluation path with missing second-innings totals must degrade to first-innings-only scoring cleanly.
